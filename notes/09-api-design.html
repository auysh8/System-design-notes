2 Core API Architectural Styles
🌐 REST (Representational State Transfer)

The most common API architectural style for web and mobile applications.

📦 Resource-Based:
Organized around data resources accessed via standard HTTP URLs and methods.
🔒 Stateless:
Every request contains all context needed. No server session state is required to process requests.

⚡ Standardized HTTP Methods:

Method Purpose Description
GET Fetching Data Retrieves resource data without modifying server state.
POST Storing / Creating Data Creates a new resource on the server.
PUT / PATCH Updating Data Replaces (PUT) or partially modifies (PATCH) an existing resource.
DELETE Deleting Data Removes a specified resource from the server.
🕸️ GraphQL (Minimal Round Trips)

A query language for APIs that allows clients to request exactly what they need and nothing more.

🎯 Single Endpoint:
Uses one single endpoint (e.g. /graphql) for all data operations.
⚡ 3 Core Operations:
  • Query ➔ Read data
  • Mutation ➔ Write / Update data
  • Subscription ➔ Real-time data stream
💡 Recommended Choice for: Complex UIs and data-heavy dashboards where reducing network round-trips and avoiding over-fetching/under-fetching is critical.
🚀 gRPC (High Performance • Least Common on Web)

A high-performance Remote Procedure Call (RPC) framework optimized for ultra-fast inter-service communication.

⚡ Protocol Buffers (Protobuf):
Uses compact binary serialization with strict schema definitions instead of heavy text JSON.
📄 Service Definition:
Methods and payload schemas are explicitly defined as RPC services inside .proto files.

📡 4 Communication Streaming Types:

1️⃣ Unary
Standard Request ➔ Response
2️⃣ Server Streaming
Single Req ➔ Stream Resp
3️⃣ Client Streaming
Stream Req ➔ Single Resp
4️⃣ Bidirectional
Two-way real-time stream
💡 Best Suited For: Microservices architecture and internal low-latency system-to-system communications.
