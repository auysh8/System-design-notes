Load Balancer Algorithms & Health Checks

7 Traffic Routing Strategies, Session Persistence, & Failover Management

★ Essential for high availability, fault tolerance & scaling!

A Load Balancer distributes incoming client traffic across multiple backend servers to ensure no single server bears too much load, preventing bottlenecks and single points of failure (SPOF).

❓ Core Question: How does a Load Balancer distribute traffic?

Load balancers utilize 7 core algorithms and strategies depending on server capacity, session requirements, and geographical proximity.

7 Load Balancing Strategies & Algorithms

🔄 1. Round Robin

Redirects incoming requests in sequential cyclical order: Server 1 ➔ Server 2 ➔ Server 3 ➔ Server 1.

💡 Best for: Environments where all servers have identical hardware specifications and request processing times are uniform.

🔗 2. Least Connections

Redirects traffic to the server currently handling the fewest active connections.

💡 Best for: Applications with long-lived persistent connections (e.g. WebSockets, streaming) where session lengths vary significantly.

⚡ 3. Least Response Time

Redirects traffic to the server that is most responsive and serving responses with the lowest latency.

💡 Best for: Providing the fastest response times when backend servers have different performance specs.

🔑 4. IP-Hash

Hashes the client's IP address to consistently map future requests from that IP to the exact same server.

💡 Best for: Session persistence (Sticky Sessions) when user state/session info is stored locally on a specific server and not synced across nodes.

⚖️ 5. Weighted Algorithms

Servers are assigned weights based on capacity. Higher-capacity servers receive a proportionally larger share of traffic.

💡 Best for: Heterogeneous server clusters where nodes have different CPU, RAM, or network bandwidth specifications.

🗺️ 6. Geographical Algorithms

Redirects traffic to the server located closest to the user's Geographical IP location.

💡 Best for: Global applications requiring latency reduction and localized content delivery (Geo-DNS routing).
⭕ 7. Consistent Hashing (Popular but Complex)

In Consistent Hashing, both servers and requests are mapped onto a conceptual Hash Ring. When a request passes through the hash function, the load balancer routes it to the server closest to that point on the ring.

Key Advantage: When adding or removing servers, only a fraction of keys need to be remapped (\(1/N\)), minimizing cache invalidation and re-sharding overhead across the cluster.

🩺 Health Checks & Failover Management
❓ How does a Load Balancer know a server is offline?

The load balancer constantly sends periodic Health Check ping requests (e.g., HTTP `/healthz` endpoints or TCP heartbeats) to all registered backend servers.

  • Server Offline Detection: If a server fails to respond within a timeout window or returns error status codes, the load balancer automatically flags it as UNHEALTHY.
  • Traffic Rerouting: It immediately stops sending traffic to the failed server and reroutes incoming requests to remaining active servers.
  • Auto-Recovery: It continues background probing, and once the server becomes active and healthy again, it re-introduces it into the server pool automatically.
