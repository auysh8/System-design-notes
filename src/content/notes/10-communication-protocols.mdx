{/*  SECTION 2: HTTP POLLING VS WEBSOCKETS  */}
<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-blue);">2</span>
        Real-Time Communication: HTTP Polling vs. WebSockets
    </div>

    <p>When clients need live updates, choosing between periodic HTTP polling and persistent WebSocket connections impacts latency and bandwidth efficiency significantly.</p>

    {/*  COMPARISON LADDERS  */}
    <div class="sequence-comparison-grid">

        {/*  HTTP POLLING CARD  */}
        <div class="sequence-box">
            <div class="sequence-header">
                <span style="color:#ef4444;">⏱️ HTTP Polling (Short Polling)</span>
                <span class="planner-tag" style="background:#fee2e2; color:#991b1b; margin:0;">Pull-Based</span>
            </div>
            
            <p style="font-size:0.875rem; color:var(--text-muted); margin-bottom:1rem;">
                Client sends repeated periodic HTTP requests asking the server if new data is available.
            </p>

            <div class="sequence-flow">
                <div class="seq-item client-req">
                    <span>💻 Client</span> ➔ <code>GET /updates</code> ➔ <span>🖥️ Server</span>
                </div>
                <div class="seq-item server-res">
                    <span>🖥️ Server</span> ➔ <code>200 OK (data)</code> ➔ <span>💻 Client</span>
                </div>
                <div class="seq-item client-req">
                    <span>💻 Client</span> ➔ <code>GET /updates</code> ➔ <span>🖥️ Server</span>
                </div>
                <div class="seq-item wasted">
                    <span>🖥️ Server</span> ➔ <code>200 OK (no new data)</code> ⚠️ <strong>Request Wasted!</strong>
                </div>
                <div class="seq-item client-req">
                    <span>💻 Client</span> ➔ <code>GET /updates</code> ➔ <span>🖥️ Server</span>
                </div>
                <div class="seq-item server-res">
                    <span>🖥️ Server</span> ➔ <code>200 OK (new data)</code> ➔ <span>💻 Client</span>
                </div>
            </div>

            <div class="goodnotes-card" style="border-top: 4px solid #ef4444; margin-top: 1rem; padding: 0.85rem;">
                <h4 style="color:#dc2626; font-size:0.95rem; margin-bottom:0.3rem;">⚠️ Major Disadvantages:</h4>
                <ul style="font-size:0.85rem; padding-left:1.2rem; margin:0;">
                    <li><strong>Increased Latency:</strong> Updates only received on next interval.</li>
                    <li><strong>Wasted Bandwidth:</strong> Constant HTTP header transfers for empty responses.</li>
                    <li><strong>Server Resource Overhead:</strong> Continual connection opening/closing strains server threads and DB.</li>
                </ul>
            </div>
        </div>

        {/*  WEBSOCKETS CARD  */}
        <div class="sequence-box">
            <div class="sequence-header">
                <span style="color:#16a34a;">⚡ WebSockets (Full-Duplex Socket)</span>
                <span class="planner-tag" style="background:#dcfce7; color:#166534; margin:0;">Push-Based</span>
            </div>

            <p style="font-size:0.875rem; color:var(--text-muted); margin-bottom:1rem;">
                Single persistent, bidirectional TCP connection established via an initial HTTP handshake.
            </p>

            <div class="sequence-flow">
                <div class="seq-item client-req" style="background:var(--pastel-blue);">
                    <span>💻 Client</span> ➔ <code>WebSocket Handshake (Upgrade)</code> ➔ <span>🖥️</span>
                </div>
                <div class="seq-item ws-push">
                    <span>🖥️ Server</span> ➔ <code>Server Push data ⚡</code> ➔ <span>💻 Client</span>
                </div>
                <div class="seq-item client-req" style="border-left-color:#a855f7;">
                    <span>💻 Client</span> ➔ <code>Client message 💬</code> ➔ <span>🖥️ Server</span>
                </div>
                <div class="seq-item ws-push">
                    <span>🖥️ Server</span> ➔ <code>Server Push data ⚡</code> ➔ <span>💻 Client</span>
                </div>
            </div>

            <div class="goodnotes-card" style="border-top: 4px solid #16a34a; margin-top: 1rem; padding: 0.85rem;">
                <h4 style="color:#16a34a; font-size:0.95rem; margin-bottom:0.3rem;">🛡️ Core Advantages:</h4>
                <ul style="font-size:0.85rem; padding-left:1.2rem; margin:0;">
                    <li><strong>Real-Time Data:</strong> Instant sub-millisecond push delivery without polling delay.</li>
                    <li><strong>Reduced Bandwidth:</strong> Minimal 2-byte frame overhead per message (no repeated HTTP headers).</li>
                    <li><strong>Bidirectional Communication:</strong> Simultaneous full-duplex messaging over 1 connection.</li>
                </ul>
            </div>
        </div>

    </div>
</div>

        {/*  1:1 DIRECT  */}
