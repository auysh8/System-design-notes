<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-pink);">4</span>
        HTTP Methods: CRUD, Safety & Idempotency Rules
    </div>

    <p>Every HTTP request verb conveys specific semantics regarding state mutations, safety, and repeatable idempotency guarantees.</p>

    <table class="table-paper">
        <thead>
            <tr>
                <th>Method</th>
                <th>CRUD Action</th>
                <th>Endpoint Example</th>
                <th>Safe?</th>
                <th>Idempotent?</th>
            </tr>
        </thead>
        <tbody>
            <tr>
                <td><mark class="hl-blue">GET</mark></td>
                <td><strong>Read</strong></td>
                <td><code>GET /api/v1/products</code></td>
                <td><span style="color:#16a34a; font-weight:700;">✅ Safe</span></td>
                <td><span style="color:#16a34a; font-weight:700;">✅ Idempotent</span></td>
            </tr>
            <tr>
                <td><mark class="hl-green">POST</mark></td>
                <td><strong>Create</strong></td>
                <td><code>POST /api/v1/products</code></td>
                <td><span style="color:#dc2626; font-weight:700;">❌ Not Safe</span></td>
                <td><span style="color:#dc2626; font-weight:700;">❌ Not Idempotent</span></td>
            </tr>
            <tr>
                <td><mark class="hl-yellow">PUT</mark></td>
                <td><strong>Update (Replace)</strong></td>
                <td><code>PUT /api/v1/products/123</code></td>
                <td><span style="color:#dc2626; font-weight:700;">❌ Not Safe</span></td>
                <td><span style="color:#16a34a; font-weight:700;">✅ Idempotent</span></td>
            </tr>
            <tr>
                <td><mark class="hl-purple">PATCH</mark></td>
                <td><strong>Update (Partial)</strong></td>
                <td><code>PATCH /api/v1/products/123</code></td>
                <td><span style="color:#dc2626; font-weight:700;">❌ Not Safe</span></td>
                <td><span style="color:#dc2626; font-weight:700;">❌ Not Idempotent</span></td>
            </tr>
            <tr>
                <td><mark class="hl-pink">DELETE</mark></td>
                <td><strong>Delete</strong></td>
                <td><code>DELETE /api/v1/products/123</code></td>
                <td><span style="color:#dc2626; font-weight:700;">❌ Not Safe</span></td>
                <td><span style="color:#16a34a; font-weight:700;">✅ Idempotent</span></td>
            </tr>
        </tbody>
    </table>

    <div class="card-grid" style="margin-top: 1.25rem;">
        <StickyNote type="yellow" title="🔒 Definition: Safe">
            <p style="font-size:0.9rem;">
                <strong>Safe Methods</strong> do NOT modify any server or database state. Calling them only inspects data (e.g. <code>GET</code>, <code>HEAD</code>).
            </p>
        </StickyNote>

        <StickyNote type="sky" title="🔁 Definition: Idempotent">
            <p style="font-size:0.9rem;">
                <strong>Idempotent Methods</strong> produce the <em>exact same server state</em> whether executed once or repeated 1,000 times (e.g. <code>PUT</code>, <code>DELETE</code>, <code>GET</code>).
            </p>
        </StickyNote>
    </div>
</div>

{/* SECTION 5: STATUS CODES & ERROR HANDLING */}
<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-purple);">5</span>
        HTTP Status Codes & Error Handling
    </div>

    <p>Clean REST APIs communicate outcome semantics using standardized 3-digit HTTP status codes:</p>

    <div class="card-grid">
        
        {/* 2xx Success */}
        <GoodNotesCard title="🟢 2xx: Success" accent="green">
            <ul style="font-size: 0.85rem; padding-left: 1.2rem; line-height: 1.7;">
                <li><strong>200 OK:</strong> Request succeeded (e.g. <code>GET /products/123</code> - successfully retrieved).</li>
                <li><strong>201 Created:</strong> New resource generated (e.g. <code>POST /products</code> - created product).</li>
                <li><strong>204 No Content:</strong> Succeeded, no response body (e.g. <code>DELETE /products/123</code>).</li>
            </ul>
        </GoodNotesCard>

        {/* 3xx Redirection */}
        <GoodNotesCard title="🟡 3xx: Redirection" accent="yellow">
            <ul style="font-size: 0.85rem; padding-left: 1.2rem; line-height: 1.7;">
                <li><strong>301 Moved Permanently:</strong> Resource relocated to new URI.</li>
                <li><strong>304 Not Modified:</strong> Cached copy valid; client can reuse.</li>
            </ul>
        </GoodNotesCard>

        {/* 4xx Client Errors */}
        <GoodNotesCard title="🟠 4xx: Client Errors" accent="orange">
            <ul style="font-size: 0.85rem; padding-left: 1.2rem; line-height: 1.7;">
                <li><strong>400 Bad Request:</strong> Invalid payload syntax or malformed query parameters.</li>
                <li><strong>401 Unauthorized:</strong> Missing or invalid authentication token.</li>
                <li><strong>403 Forbidden:</strong> Authenticated but lacks required permission.</li>
                <li><strong>404 Not Found:</strong> Resource does not exist (e.g. <code>GET /products/999</code>).</li>
            </ul>
        </GoodNotesCard>

        {/* 5xx Server Errors */}
        <GoodNotesCard title="🔴 5xx: Server Errors" accent="pink">
            <ul style="font-size: 0.85rem; padding-left: 1.2rem; line-height: 1.7;">
                <li><strong>500 Internal Server Error:</strong> Unexpected crash or unhandled server-side exception.</li>
                <li><strong>502 Bad Gateway:</strong> Upstream server failure via proxy / load balancer.</li>
                <li><strong>503 Service Unavailable:</strong> Server overloaded or undergoing maintenance.</li>
            </ul>
        </GoodNotesCard>

    </div>
</div>

{/* SECTION 6: BEST PRACTICES & POOR VS GOOD DESIGN */}
<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-orange);">6</span>
        API Design Best Practices: Poor vs. Good Design
    </div>

    <StickyNote type="sky" title="📋 4 Core API Design Principles:">
        <ol style="font-size: 0.95rem; padding-left: 1.2rem; line-height: 1.7; margin: 0.25rem 0 0 0;">
            <li><strong>Use plural nouns for resources:</strong> e.g., <code>/users</code>, <code>/orders</code> (never verbs).</li>
            <li><strong>Keep URLs consistent and hierarchical:</strong> Reflect resource parentage cleanly (<code>/products/123/reviews</code>).</li>
            <li><strong>Support filtering, sorting, and pagination:</strong> Always provide query modifiers on collection routes.</li>
            <li><strong>Version your APIs:</strong> Explicitly prefix routes with version identifiers (<code>/api/v1/...</code>) to prevent breaking client changes.</li>
        </ol>
    </StickyNote>

    <h4 style="font-family: var(--font-title); font-size: 1.15rem; margin: 1.75rem 0 0.75rem 0;">
        ⚖️ Poor Design vs. Good Design Direct Comparison:
    </h4>

    <table class="table-paper">
        <thead>
            <tr>
                <th style="width: 50%; color: #dc2626;">❌ Poor API Design (Anti-Pattern)</th>
                <th style="width: 50%; color: #16a34a;">✅ Good API Design (RESTful Standard)</th>
            </tr>
        </thead>
        <tbody>
            <tr>
                <td><code>GET /getUser/123</code> <br /><span style="font-size:0.8rem; color:var(--text-muted);">Verb in URI path + singular noun</span></td>
                <td><code>GET /api/v1/users/123</code> <br /><span style="font-size:0.8rem; color:var(--text-muted);">HTTP GET verb with plural noun</span></td>
            </tr>
            <tr>
                <td><code>POST /users/123/delete</code> <br /><span style="font-size:0.8rem; color:var(--text-muted);">Action verb endpoint instead of HTTP method</span></td>
                <td><code>DELETE /api/v1/users/123</code> <br /><span style="font-size:0.8rem; color:var(--text-muted);">Clean HTTP DELETE verb on target URI</span></td>
            </tr>
            <tr>
                <td><code>GET /products?page=3</code> <br /><span style="font-size:0.8rem; color:var(--text-muted);">Incomplete pagination without limits or sort order</span></td>
                <td><code>GET /api/v1/products?page=3&limit=25&sort=price:desc</code> <br /><span style="font-size:0.8rem; color:var(--text-muted);">Full query modifiers with limit and sort</span></td>
            </tr>
        </tbody>
    </table>
