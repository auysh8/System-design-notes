<div class="note-section">
    <p>Relational databases use <mark class="hl-yellow">SQL (Structured Query Language)</mark> for data definition and manipulation. Data is organized strictly into rows and columns.</p>

    <CodeSticker title="SQL: Create & Insert Example" copyLabel="Copy SQL">
```sql
CREATE TABLE Customers (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100),
    age INTEGER,
    email VARCHAR(100)
);

INSERT INTO Customers (id, name, age, email)
VALUES (123, 'John Doe', 30, 'johndoe@example.com');
```
    </CodeSticker>

    <h3 style="font-family: var(--font-title); font-size: 1.4rem; font-weight: 800; margin: 2rem 0 0.5rem 0;">🔗 Complex Join Operations & Foreign Keys</h3>
    <p>SQL excels at joining related entities. For example, an <mark class="hl-blue">Orders</mark> table links to <mark class="hl-blue">Customers</mark> and <mark class="hl-blue">Products</mark> via Foreign Keys.</p>

    <CodeSticker title="SQL: Orders Table Schema with Foreign Keys" copyLabel="Copy SQL">
```sql
CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    product_id INT,
    quantity INT,
    order_date DATE,
    FOREIGN KEY (customer_id) REFERENCES Customers(id),
    FOREIGN KEY (product_id) REFERENCES Products(id)
);
```
    </CodeSticker>
