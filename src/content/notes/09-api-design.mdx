        {/*  STATUS CODES  */}
        <GoodNotesCard title="🔢 HTTP Status Code Categories" accent="blue">
            <ul style="font-size: 0.9rem; margin-top: 0.5rem; padding-left: 1.2rem;">
                <li><strong style="color:#16a34a;">2xx (Success):</strong> Request was received, understood, and accepted (e.g. <code>200 OK</code>, <code>201 Created</code>).</li>
                <li><strong style="color:#d97706;">3xx (Redirection):</strong> Further action needed to complete request (e.g. <code>301 Moved</code>, <code>304 Not Modified</code>).</li>
                <li><strong style="color:#dc2626;">4xx (Client Error):</strong> Invalid request or unauthorized client (e.g. <code>400 Bad Request</code>, <code>401 Unauthorized</code>, <code>404 Not Found</code>).</li>
                <li><strong style="color:#9333ea;">5xx (Server Error):</strong> Server failed to fulfill a valid request (e.g. <code>500 Internal Error</code>, <code>502 Bad Gateway</code>, <code>503 Service Unavailable</code>).</li>
            </ul>
        </GoodNotesCard>

        {/*  COMMON HEADERS  */}
        <GoodNotesCard title="📋 5 Common HTTP Headers" accent="green">
            <ul style="font-size: 0.9rem; margin-top: 0.5rem; padding-left: 1.2rem;">
                <li><code>Content-Type</code>: Tells client/server MIME type of data (e.g. <code>application/json</code>).</li>
                <li><code>Authorization</code>: Carries credentials/tokens for authentication (e.g. <code>Bearer &lt;token&gt;</code>).</li>
                <li><code>Accept</code>: Specifies media types acceptable for the response.</li>
                <li><code>Cache-Control</code>: Directives for caching mechanisms in browsers/CDNs (e.g. <code>max-age=3600</code>).</li>
                <li><code>User-Agent</code>: Identifies the requesting browser, OS, and client software.</li>
            </ul>
        </GoodNotesCard>

{/*  SECTION 4: HTTPS & TRANSPORT SECURITY  */}
<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-pink);">4</span>
        HTTPS (HTTP + TLS/SSL Encryption)
    </div>

    <StickyNote type="sky" title="🔒 What is HTTPS?">
        <p style="font-size: 1rem; line-height: 1.5;">
            <strong>HTTPS = HTTP + TLS/SSL Encryption</strong><br />
            Protects data in transit from eavesdropping, interception, and tampering across public networks.
        </p>
    </StickyNote>

    {/*  BENEFITS VS RISKS GRID  */}
    <div class="card-grid" style="margin-top: 1.5rem;">

        {/*  BENEFITS OF HTTPS  */}
        <GoodNotesCard title="🛡️ Key Benefits of HTTPS" accent="green">
            <ul style="font-size: 0.9rem; margin-top: 0.5rem; padding-left: 1.2rem;">
                <li><strong>Data Encryption:</strong> Encrypts transmitted packets so eavesdroppers cannot read raw sensitive data.</li>
                <li><strong>Data Integrity:</strong> Detects and prevents any data alteration, packet injection, or corruption during transit.</li>
                <li><strong>Authentication:</strong> Verifies server identity via trusted SSL/TLS certificates, preventing DNS spoofing.</li>
                <li><strong>SEO Benefits:</strong> Search engines (e.g. Google) penalize plain HTTP and rank HTTPS websites higher.</li>
            </ul>
        </GoodNotesCard>

        {/*  RISKS WITHOUT HTTPS  */}
        <GoodNotesCard title="⚠️ Critical Risks Without HTTPS" borderColor="#ef4444">
            <ul style="font-size: 0.9rem; margin-top: 0.5rem; padding-left: 1.2rem;">
                <li><strong>Man-in-the-Middle (MITM) Attacks:</strong> Adversaries on public Wi-Fi intercept and monitor plain data streams.</li>
                <li><strong>Data Tampering:</strong> Bad actors inject ads, malicious scripts, or alter transaction payloads in transit.</li>
                <li><strong>Information Theft:</strong> Cleartext passwords, session cookies, credit card numbers, and PII get stolen.</li>
                <li><strong>Loss of User Trust:</strong> Modern browsers display red "Not Secure" warnings, driving visitors away.</li>
            </ul>
        </GoodNotesCard>

    </div>
</div>

{/*  SECTION 5: CORE ARCHITECTURAL STYLES  */}
<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-purple);">5</span>
        Core API Architectural Styles: REST, GraphQL, & gRPC
    </div>

    {/*  REST CARD  */}
    <StickyNote type="sky" title="🌐 1. REST (Representational State Transfer)">
        <p style="font-size: 0.95rem; margin-bottom: 0.75rem;">The universal industry-standard API architectural style for web, cloud, and mobile clients.</p>

        <div style="display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); gap: 1rem; margin-top: 1rem;">
            <div style="background: var(--paper-card); padding: 1rem; border-radius: 8px; border: 1px solid var(--border-soft);">
                <strong>📦 Resource-Based:</strong>
                <div style="font-size:0.85rem; margin-top:0.3rem;">Structured around intuitive resource endpoints (e.g. <code>/api/v1/users</code>, <code>/api/v1/orders</code>) using standard HTTP methods.</div>
            </div>

            <div style="background: var(--paper-card); padding: 1rem; border-radius: 8px; border: 1px solid var(--border-soft);">
                <strong>🔒 Stateless:</strong>
                <div style="font-size:0.85rem; margin-top:0.3rem;">Every request contains complete authorization and parameters; server retains no client session state between requests.</div>
            </div>
        </div>
    </StickyNote>

    {/*  GRAPHQL CARD  */}
    <StickyNote type="lavender" title="🕸️ 2. GraphQL (Minimal Round Trips & Precise Fetching)">
        <p style="font-size: 0.95rem; margin-bottom: 0.75rem;">A client-driven query language for APIs that eliminates <strong>over-fetching</strong> and <strong>under-fetching</strong>.</p>

        <div style="display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); gap: 1rem; margin-top: 1rem;">
            <div style="background: var(--paper-card); padding: 1rem; border-radius: 8px; border: 1px solid var(--border-soft);">
                <strong>🎯 Single Endpoint:</strong>
                <div style="font-size:0.85rem; margin-top:0.3rem;">All client queries and mutations route through a single unified endpoint (e.g. <code>/graphql</code>).</div>
            </div>

            <div style="background: var(--paper-card); padding: 1rem; border-radius: 8px; border: 1px solid var(--border-soft);">
                <strong>⚡ 3 Core Operations:</strong>
                <ul style="font-size:0.85rem; margin:0.3rem 0 0 1rem; padding:0;">
                    <li><code>Query</code> ➔ Read and retrieve exact required fields</li>
                    <li><code>Mutation</code> ➔ Create, update, or delete server data</li>
                    <li><code>Subscription</code> ➔ Real-time WebSocket event streaming</li>
                </ul>
            </div>
        </div>

        <div style="margin-top: 1rem; font-size: 0.875rem;">
            💡 <strong>Recommended Choice for:</strong> Complex frontend UIs, mobile apps with bandwidth constraints, and aggregating multi-service dashboards into a single request.
        </div>
    </StickyNote>

    {/*  gRPC CARD  */}
    <StickyNote type="yellow" title="🚀 3. gRPC (High Performance Binary RPC)">
        <p style="font-size: 0.95rem; margin-bottom: 0.75rem;">A high-throughput, low-latency Remote Procedure Call framework created by Google for microservices.</p>

        <div style="display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); gap: 1rem; margin-top: 1rem;">
            <div style="background: var(--paper-card); padding: 1rem; border-radius: 8px; border: 1px solid var(--border-soft);">
                <strong>⚡ Protocol Buffers (Protobuf):</strong>
                <div style="font-size:0.85rem; margin-top:0.3rem;">Uses ultra-compact <strong>binary serialization</strong> instead of heavy JSON text, cutting bandwidth and parse overhead.</div>
            </div>

            <div style="background: var(--paper-card); padding: 1rem; border-radius: 8px; border: 1px solid var(--border-soft);">
                <strong>📄 Service Definition (.proto):</strong>
                <div style="font-size:0.85rem; margin-top:0.3rem;">Strict contract-first schemas defined in <code>.proto</code> files with auto-generated client/server SDKs in multiple languages.</div>
            </div>
        </div>

        <h4 style="font-family: var(--font-title); font-size: 1.05rem; margin: 1.25rem 0 0.5rem 0;">📡 4 Communication Streaming Modes:</h4>
        <div style="display: grid; grid-template-columns: repeat(auto-fit, minmax(180px, 1fr)); gap: 0.75rem;">
            <div style="background: var(--paper-card); padding: 0.75rem; border-radius: 6px; font-size: 0.85rem; border: 1px solid var(--border-soft);">
                1️⃣ <strong>Unary</strong><br /><span style="color:var(--text-muted);">Single Req ➔ Single Resp</span>
            </div>
            <div style="background: var(--paper-card); padding: 0.75rem; border-radius: 6px; font-size: 0.85rem; border: 1px solid var(--border-soft);">
                2️⃣ <strong>Server Streaming</strong><br /><span style="color:var(--text-muted);">Single Req ➔ Stream Resp</span>
            </div>
            <div style="background: var(--paper-card); padding: 0.75rem; border-radius: 6px; font-size: 0.85rem; border: 1px solid var(--border-soft);">
                3️⃣ <strong>Client Streaming</strong><br /><span style="color:var(--text-muted);">Stream Req ➔ Single Resp</span>
            </div>
            <div style="background: var(--paper-card); padding: 0.75rem; border-radius: 6px; font-size: 0.85rem; border: 1px solid var(--border-soft);">
                4️⃣ <strong>Bidirectional</strong><br /><span style="color:var(--text-muted);">Two-way continuous stream</span>
            </div>
        </div>

        <div style="margin-top: 1rem; font-size: 0.875rem;">
            💡 <strong>Best Suited For:</strong> Internal backend-to-backend microservices, high-frequency trading, and IoT telemetry pipelines.
        </div>
    </StickyNote>
</div>
