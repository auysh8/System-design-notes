{/* SECTION 2: TOKEN-BASED AUTH & JWT */}
<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-blue);">2</span>
        Stateless Token-Based Authentication (JWT Bearer Flow)
    </div>

    <p>To scale across horizontally distributed microservices without hitting a centralized session store on every HTTP call, modern systems use <mark class="hl-blue">Stateless JWT Bearer Tokens</mark>:</p>

    {/* JWT Flow Sequence Ladder */}
    <DiagramPaper title="⚡ Stateless JWT Bearer Authentication Flow">
        <div style="display: flex; flex-direction: column; gap: 1rem; max-width: 720px; margin: 0 auto; font-family: var(--font-body);">
            
            {/* Header */}
            <div style="display: grid; grid-template-columns: 1fr 1fr 1fr; text-align: center; border-bottom: 2px solid var(--border-soft); padding-bottom: 0.5rem; font-weight: 800;">
                <div><span style="background: var(--paper-card); padding: 0.3rem 0.8rem; border-radius: 6px; border: 1.5px solid var(--border-soft);">📱 Client</span></div>
                <div><span style="background: var(--pastel-yellow); padding: 0.3rem 0.8rem; border-radius: 6px; border: 1.5px solid var(--border-soft);">🛡️ Auth Server</span></div>
                <div><span style="background: var(--pastel-green); padding: 0.3rem 0.8rem; border-radius: 6px; border: 1.5px solid var(--border-soft);">🌐 API Server</span></div>
            </div>

            {/* Sequence Steps */}
            <div style="background: var(--paper-bg); border: 1.5px dashed var(--border-soft); border-radius: 10px; padding: 1.25rem; font-size: 0.88rem; line-height: 1.85;">
                <div><strong>① Client ➔ Auth Server:</strong> Login request with user credentials.</div>
                <div><strong>② Auth Server:</strong> Validate credentials against database.</div>
                <div><strong>③ Auth Server ➔ Client:</strong> Issue digitally signed <strong>JWT Token</strong> (containing user ID, roles, and expiry).</div>
                <div style="border-top: 1px solid var(--border-soft); margin: 0.5rem 0; padding-top: 0.5rem;">
                    <strong>④ Client ➔ API Server:</strong> Send request with header: <code>Authorization: Bearer &lt;jwt_token&gt;</code>.
                </div>
                <div>
                    <strong>⑤ API Server:</strong> <span style="color: #16a34a; font-weight: 700;">Verify cryptographic signature locally</span> (using public key / secret) — <strong>zero database lookups needed!</strong>
                </div>
                <div><strong>⑥ API Server ➔ Client:</strong> Return requested data directly.</div>
            </div>

        </div>
    </DiagramPaper>

    <div class="card-grid" style="margin-top: 1.25rem;">
        <GoodNotesCard title="🚀 Core Advantage" accent="green">
            <p><strong>Completely Stateless:</strong> Any API server across multiple regions can verify the token without querying a database or cache.</p>
        </GoodNotesCard>

        <GoodNotesCard title="⚠️ Core Trade-Off" accent="pink">
            <p><strong>Revocation Difficulty:</strong> Because verification is stateless, invalidating a leaked token before it expires requires a token blacklist or short expiration times.</p>
        </GoodNotesCard>
    </div>
</div>

{/* SECTION 3: ACCESS & REFRESH TOKENS */}
<div class="note-section">
    <div class="section-title">
        <span class="title-badge" style="background: var(--pastel-pink);">3</span>
        Access & Refresh Token Lifecycle
    </div>

    <p>To balance security and user experience, systems implement a <mark class="hl-pink">Dual-Token Lifecycle</mark>:</p>

    <div style="display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); gap: 1rem; margin-bottom: 1.25rem;">
        <div style="background: #fee2e2; border: 2px solid #ef4444; border-radius: 10px; padding: 1rem; text-align: center;">
            <div style="font-weight: 800; color: #991b1b; font-size: 1.05rem;">⚡ Access Token</div>
            <div style="font-size: 1.5rem; font-weight: 800; color: #7f1d1d; margin: 0.35rem 0;">15 min – 1 hr</div>
            <div style="font-size: 0.8rem; color: #991b1b;">Short-lived; sent with API calls; limits blast radius if stolen.</div>
        </div>

        <div style="background: #dcfce7; border: 2px solid #22c55e; border-radius: 10px; padding: 1rem; text-align: center;">
            <div style="font-weight: 800; color: #166534; font-size: 1.05rem;">🔄 Refresh Token</div>
            <div style="font-size: 1.5rem; font-weight: 800; color: #14532d; margin: 0.35rem 0;">7 to 30 days</div>
            <div style="font-size: 0.8rem; color: #166534;">Long-lived; securely stored; used only to mint fresh access tokens.</div>
        </div>
    </div>

    {/* Token Renewal Ladder */}
    <DiagramPaper title="🔄 Access & Refresh Token Renewal Sequence">
        <div style="display: flex; flex-direction: column; gap: 1rem; max-width: 720px; margin: 0 auto; font-family: var(--font-body);">
            
            {/* Header */}
            <div style="display: grid; grid-template-columns: 1fr 1fr 1fr; text-align: center; border-bottom: 2px solid var(--border-soft); padding-bottom: 0.5rem; font-weight: 800;">
                <div><span style="background: var(--paper-card); padding: 0.3rem 0.8rem; border-radius: 6px; border: 1.5px solid var(--border-soft);">📱 Client</span></div>
                <div><span style="background: var(--pastel-yellow); padding: 0.3rem 0.8rem; border-radius: 6px; border: 1.5px solid var(--border-soft);">🛡️ Auth Server</span></div>
                <div><span style="background: var(--pastel-green); padding: 0.3rem 0.8rem; border-radius: 6px; border: 1.5px solid var(--border-soft);">🌐 API Server</span></div>
            </div>

            {/* Steps */}
            <div style="background: var(--paper-bg); border: 1.5px dashed var(--border-soft); border-radius: 10px; padding: 1.25rem; font-size: 0.88rem; line-height: 1.85;">
                <div><strong>① Client ➔ Auth Server:</strong> Login request with user credentials.</div>
                <div><strong>② Auth Server ➔ Client:</strong> Issue both <strong>Access Token</strong> (15 min) and <strong>Refresh Token</strong> (30 days).</div>
                <div><strong>③ Client ➔ API Server:</strong> Make API request with expired Access Token.</div>
                <div><strong>④ API Server ➔ Client:</strong> Return <code>401 Unauthorized</code> (Access Token Expired).</div>
                <div><strong>⑤ Client ➔ Auth Server:</strong> Send Refresh Token to token renewal endpoint (<code>POST /auth/refresh</code>).</div>
                <div><strong>⑥ Auth Server ➔ Client:</strong> Validate Refresh Token & issue a <strong>New Access Token</strong>.</div>
                <div><strong>⑦ Client ➔ API Server:</strong> Re-send original request with the new Access Token.</div>
                <div><strong>⑧ API Server ➔ Client:</strong> Success response with requested data.</div>
            </div>

        </div>
    </DiagramPaper>

    <StickyNote type="coral" title="🚨 Essential Security Golden Rule">
        <p style="font-size:0.95rem; line-height:1.6;">
            <strong>Never store Refresh Tokens in <code>localStorage</code> or <code>sessionStorage</code>!</strong><br />
            Any Cross-Site Scripting (XSS) vulnerability allows attackers to extract local storage tokens. Always store Refresh Tokens inside <strong><code>HttpOnly</code>, <code>Secure</code>, <code>SameSite=Strict</code> cookies</strong> so JavaScript cannot access them.
        </p>
    </StickyNote>
</div>

                <div><span style="background: var(--pastel-green); padding: 0.25rem 0.5rem; border-radius: 4px; border: 1.5px solid var(--border-soft);">🖥️ Your Backend</span></div>

                <div><strong>① User ➔ Your App:</strong> User clicks <em>"Sign in with Google"</em>.</div>
                <div><strong>② Your App ➔ Google Identity:</strong> Redirect to OIDC authorization endpoint (with <code>scope=openid profile email</code>).</div>
                <div><strong>③ Google Identity ➔ User:</strong> Display Google Sign-in screen.</div>
                <div><strong>④ User ➔ Google Identity:</strong> Enter credentials and confirm consent.</div>
                <div><strong>⑤ Google Identity ➔ Your App:</strong> Return <strong>Authorization Code</strong>.</div>
